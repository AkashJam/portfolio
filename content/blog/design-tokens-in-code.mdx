Mockups are useful for deciding what something should look like. They're a bad place for that
decision to actually live, because a mockup and the running site have no mechanism forcing them to
stay in agreement — the mockup doesn't know the site changed, and the site doesn't know the mockup
did either.

## Where the disagreement usually lives

The default failure mode is a color or spacing value typed directly into JSX wherever it's needed.
That works until the value needs to change, at which point "change it" means finding every place it
was typed, by hand, hoping none were missed and none were slightly different from what they should
have matched in the first place.

## One source, mapped in

This site's design tokens live in exactly one place — CSS custom properties in `globals.css` — mapped
into Tailwind v4's `@theme` so every utility class resolves back to the same source. The mockups are a
visual reference only. Where a mockup and the token layer disagreed during the build, the tokens in
code won, on purpose, never the other way around — the mockup doesn't get a vote once the system is
running.

```text
globals.css (CSS custom properties)
        │
        ▼
   Tailwind @theme
        │
        ▼
  every utility class, every component
```

## What this actually bought, concretely

Partway through the build, a design refresh touched ambient background elements and reworked color
usage across two full pages. Because every color reference routed through the token layer instead of
being typed inline, that refresh was a change to the token definitions — a targeted diff — instead of
a search-and-replace across dozens of files hoping nothing was missed.

## The part that's easy to skip

Wiring shadcn/ui and Radix-based primitives to the same token layer, rather than letting component
libraries bring their own default palette, is what keeps the system actually single-sourced.
Accessibility behavior — focus states, contrast — comes from the primitives by construction; the
tokens just make sure what they render matches everything else on the page instead of drifting into
its own visual language.

## Where this came from

This is the real setup behind this site's design system: tokens as CSS custom properties, mapped into
Tailwind's `@theme`, with mockups treated as a starting reference rather than a parallel source of
truth. The mid-build design refresh that validated the approach actually happened — it's the reason
this pattern is worth writing down rather than just asserting.
