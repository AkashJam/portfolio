Self-serve tooling for a non-engineering team means the person clicking "cancel" isn't going to trace
through what that button does before they click it. If "cancel" means a row disappears, the system's
safety depends entirely on nobody ever clicking it by mistake — which is a bet you will eventually
lose.

## Delete is a one-way door

A hard delete doesn't just remove a row, it removes the history of why the row existed and what state
it was in before it went away. When the thing deleted was a paying customer's contract, "restore from
backup" is not the same as "undo" — it's slower, it's a different team, and it's the kind of incident
report nobody wants to write.

## Modeling the lifecycle as an explicit state machine

The fix is refusing to let "gone" be a real state. A contract moves through draft, active, and
suspended — an explicit, finite set of states with defined transitions between them — and there is no
transition that means "row no longer exists." Cancellation is suspension: reversible, visible, and
exactly as findable after the fact as before it.

```text
draft ──▶ active ──▶ suspended
            ▲             │
            └─────────────┘
         (reactivate is just another transition)
```

## What this buys, concretely

An accidental cancellation is recoverable by flipping the state back, not by escalating to whoever
has database access. The full history of a contract's lifecycle stays queryable — every transition is
still a row, not a gap where a row used to be. And because "suspended" is a state like any other, the
same authorization and audit logic that governs every other transition governs this one too, instead
of delete needing its own special-cased, harder-to-audit code path.

## The honest tradeoff

Nothing is ever really gone, which means the table doesn't shrink and every state transition is
permanent history you're keeping. That's a deliberate trade: a little more storage and a little more
schema discipline, in exchange for making the worst version of "I clicked the wrong thing" a two-click
fix instead of an incident.

## Where this came from

This is the real lifecycle model in Lifeed's internal admin tool: draft, active, suspended, no hard
delete, cancellation as a reversible transition. It's the direct answer to handing delete-adjacent
power to a team that isn't reading the code underneath the button — make the destructive-feeling
action non-destructive by construction.
